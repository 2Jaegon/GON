# 요구 구체화 대체 카드 (`cards/refine.md`)

외부 인터뷰 스킬이 없을 때 이 카드의 절차를 따른다.

## 1. 목적
사용자의 모호한 요청에서 **목표, 산출물, 제약사항, 가정, 수용 기준**을 명확히 정의하여 `.gon/<run_id>/brief.md`를 작성한다.

## 2. 질문 원칙
- 실행에 반드시 필요한 치명적 누락(blocking)만 묻는다.
- 답을 고르기 쉽도록 **추천 답안**을 항상 함께 제시한다.
- 사소하거나 되돌릴 수 있는 결정은 합리적인 기본값을 정하고 `assumptions`에 명시한다.
- 질문 횟수 한도: FAST는 0회, STANDARD는 1회(최대 5개 질문), DEEP은 최대 2회.

## 3. `brief.md` 산출물 양식
```markdown
# 작업 명세서 (brief)

## 목표 (Objective)
- <무엇을 달성하고자 하는가>

## 산출물 (Deliverables)
- <생성되거나 수정될 구체적 결과물>

## 제약사항 (Constraints)
- <보존해야 할 불변조건, 건드리지 말아야 할 파일 등>

## 기본 가정 (Assumptions)
- [가정 1] 영향도: 낮음, 가역적: 예

## 수용 기준 (Acceptance Criteria)
- [ ] 기준 1: <검증 가능한 동작>
- [ ] 기준 2: <테스트 통과>
```
