# Architecture Decision Records (ADR-002 to ADR-010)

## ADR-002: Disallow Arbitrary Shell Execution on Web / API Servers
- **Context:** Remote code execution vulnerabilities arise when web application backends directly invoke developer shell commands (`child_process.exec`).
- **Decision:** The API backend and web UI process NEVER execute arbitrary shell commands on behalf of users. Shell commands and workspace file changes occur strictly within `apps/local-runner` (on the user's paired device) or ephemeral `Cloud Sandbox` containers.

## ADR-003: SSE for UI Streaming and Outbound WebSocket for Local Runner
- **Context:** Web users require live progress updates, logs, and token counters. Local developer machines are frequently behind NAT and firewalls.
- **Decision:** Web UI connects to `/api/v1/workspaces/:w/runs/:id/events` using Server-Sent Events (SSE) with `Last-Event-ID` reconnection replay. Local runners initiate outbound WebSocket connections to `/api/v1/runner/ws` using mutual device authentication.

## ADR-004: PostgreSQL / Database as State Source of Truth (Redis for Queue/Cache)
- **Context:** Queue crashes, network partitions, or Redis restarts must not destroy run history, approved plan snapshots, or usage audit logs.
- **Decision:** Relational DB (PostgreSQL / repository layer) stores all entities, run state transitions, outbox events, and usage records. Redis is utilized strictly as a transient job broker (BullMQ) and cache.

## ADR-005: GitHub App with Scoped Installations Over Personal OAuth Tokens
- **Context:** Personal GitHub OAuth tokens grant overly broad user account permissions across all personal repositories and lack enterprise governance.
- **Decision:** GitHub integration uses a GitHub App with per-repository installation grants, issuing short-lived ephemeral installation access tokens on demand.

## ADR-006: Independent Authentication, Permission, and Billing Ownership per Provider
- **Context:** Different AI providers (OpenAI, Anthropic, Google) have distinct terms, rate limits, latency profiles, and cost structures.
- **Decision:** Each provider connection model (`LOCAL_NATIVE_CLI`, `USER_API_KEY`, `ORG_API_KEY`, `PARTNER_OAUTH_APPROVED`) defines its own legal gate, capability matrix, and billing ownership.

## ADR-007: Top-Level Orchestrator Governance over Sub-Skills (No Unbounded Loops)
- **Context:** Sub-skills (e.g. Superpowers, ECC specialists, find-skills) can generate circular tool calls or unconstrained infinite loops, exploding token consumption.
- **Decision:** ASO Web acts as the supreme orchestrator. It manages task DAGs, enforces hard budget caps (wall time, token limit, retry attempts), and treats skills as modular functions rather than sovereign unbounded agents.

## ADR-008: Local Runner as User Device Boundary with Signed Job Contracts
- **Context:** A compromised server or malicious request must not arbitrarily access user files or delete local disks.
- **Decision:** Local Runner requires explicit workspace directory grants from the user, verifies cryptographic job contract signatures, rejects path traversals (`..`, symlinks pointing outside), and requires explicit approval for destructive actions.

## ADR-009: Strict Separation of Inference Cost Ledger and SaaS Billing Ledger
- **Context:** Confusing third-party model inference tokens with ASO platform subscription fees creates billing disputes and false accounting.
- **Decision:** Two independent ledgers: `usage_ledger` (measures raw provider tokens, wall time, confidence status) and `billing_ledger` (ASO platform plan, workspace seats, cloud credits).

## ADR-010: Server-Side Skill Metadata Catalog with Cryptographic Provenance
- **Context:** Dynamic downloading of unverified external AI skills introduces severe supply-chain attack vectors.
- **Decision:** Skill registry tracks canonical name, version, git commit hash, sha256 content digest, license, and risk classification. External skill auto-loading is disabled by default.
