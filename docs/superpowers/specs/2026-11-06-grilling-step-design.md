# Grilling 단계: 모호한 요청을 계획 전에 다듬기 설계

> **대체됨 (2026-11-06):** 분류기·고정 계획 기반 흐름은 `2026-11-06-agent-session-design.md`로 대체됐다. 카탈로그·배지·승인 취지만 그 문서로 이어진다.

- 날짜: 2026-11-06
- 범위: `packages/aso-core`(모호함 판별), `apps/api/src/services/orchestrator-service.ts`(질문 단계), `packages/contracts`(이벤트·상태), `apps/web/public`(배지·질문 카드)

## 1. 의도

지금은 `mattpocock-skills:grilling`이 카탈로그에 등록만 돼 있고, 스킬 라우터는 고르지 않으며, 요구사항 정리(`IntentRefiner`)는 질문 없이 고정 문구만 채운다. `/mattpocock-skills:grilling`을 입력해도 서버는 글자로만 넘긴다. 그래서 어떤 질문에도 grilling이 동작하지 않는다.

목표는 구현·조사 요청이 모호할 때, 계획을 세우기 전에 AI가 핵심 질문을 한 번에 묶어 묻고(각 질문에 추천 답), 그 답으로 요구사항을 채운 뒤 계획으로 넘어가는 것이다. 사용자가 지금 grilling이 돌고 있다는 걸 배지로 알 수 있게 한다.

## 2. 목표 / 비목표 / 반목표

**목표**
1. `standard`·`deep` 실행 중 모호한 요청에서만 질문 단계가 돈다.
2. 질문은 한 라운드, 3~4개, 질문마다 추천 답을 붙인다.
3. 답변 말풍선 위에 `Grilling · 요구사항 다듬는 중` 배지를 띄우고, 질문 카드에서 질문별로 [추천대로] 또는 직접 입력으로 답한다. [모두 추천대로] 버튼도 있다.
4. 답은 요구사항(`goals`/`constraints`/`acceptanceCriteria`)에 들어가고 계획 화면에서 보인다.
5. 입력창 왼쪽 위 등에서 "이번 요청은 질문 없이 바로"를 고를 수 있다(건너뛰기).

**비목표**
- 대화(`chat`)·`fast`·`image` 실행에는 띄우지 않는다.
- 여러 라운드 반복 질문, 질문 품질 평가 루프.

**반목표**
- 단순 질문이나 명확한 요청에도 질문을 던져 흐름을 막는 것.
- 사용자가 답하지 않았는데 추천 답을 사용자 결정처럼 계획에 넣는 것 — [추천대로]를 눌렀을 때만 넣는다.

## 3. 모호함 판별 (언제 질문하나)

`standard`/`deep`으로 분류된 요청 중 아래 중 2개 이상이면 질문 단계를 연다(규칙 기반, 모델 호출 없음).
- 요청이 짧다(공백 제외 25자 미만).
- 대상이 없다: 파일·화면·API·기능 이름 같은 명사 단서가 없다.
- 완료 기준이 없다: "~되면", "~까지", "테스트", "기준", 숫자 목표 같은 단서가 없다.
- "알아서", "좋게", "적당히", "대충" 같은 위임 표현이 있다.

예시: "로그인 만들어줘" → 질문함(짧음 + 완료 기준 없음). "`apps/api`에 /health 엔드포인트 추가하고 200 응답 테스트까지" → 질문 안 함.

## 4. 정해진 동작

1. 분류 뒤, 모호하면 실행 상태를 `clarifying`으로 두고 `grill:started` 이벤트를 남긴다.
2. 선택된 연결의 `executeChat`에 "요청 + 질문 3~4개를 JSON으로(질문, 왜 묻는지 한 줄, 추천 답)" 형식을 보내고 결과를 `grill:questions` 이벤트로 남긴다. JSON이 깨지면 질문 단계를 건너뛰고 지금처럼 계획으로 간다.
3. 사용자가 답을 보내면 `grill:answered` 이벤트와 함께 요구사항에 반영하고 기존 `refining → planning` 흐름을 잇는다.
4. 배지: 질문 단계 동안 답변 영역 위에 작은 칩(불꽃 아이콘 + `Grilling` + `요구사항 다듬는 중`), 답변이 끝나면 `Grilling 완료 · 3개 답변 반영`으로 바뀌어 남는다.

## 5. 방식

규칙으로 "질문할지"만 정하고 질문 내용은 모델이 쓰는 방식 하나로 정했다. 모든 요청을 모델에게 "질문할지" 묻는 방식은 호출이 매번 늘고 단순 요청도 막을 위험이 있어 제외했다. 질문 템플릿을 고정하는 방식은 요청마다 다른 빈칸을 못 짚어 제외했다. 사용자가 이 방향(구현·조사 요청에서 대상·완료 기준이 빠졌을 때 3~4개 묶음 질문, 추천 답, 배지)을 골랐다(2026-11-06).

## 6. 빌더에게 맡기는 것

- 판별 단서 단어 목록의 세부, 배지·카드 시각 디자인(기존 `style.css` 톤 유지).
- 이벤트 payload 모양, 상태 이름이 기존 `RunStatusSchema`와 충돌하지 않게 맞추기.
