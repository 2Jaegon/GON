## 1. 의도

사용자가 채팅에서 어떤 모델(예: Claude)을 고른 상태든 "강아지가 잔디밭에서 민들레 보는 이미지 만들어줘"라고 하면, 앱이 사용자가 모아 둔 프롬프트 규칙으로 좋은 생성 프롬프트를 만들고, 사용자가 한 번 확인하면 Gemini가 이미지를 만들어 채팅에 보여준다.

지금은 이 요청이 개발 작업으로 분류되어 "타입 계약 구현" 같은 엉뚱한 계획을 만들고 실패한다(2026-11-06 실행 기록).

## 2. 목표 / 비목표 / 반목표

**목표**
1. 이미지 생성 요청을 채팅·개발과 구분해 `image` 흐름으로 보낸다.
2. 요청을 13개 카테고리 중 하나로 판별하고, 그 카테고리 템플릿과 공통 규칙 블록으로 프롬프트를 만든다.
3. 프롬프트는 지금 고른 채팅 모델이 영어로 쓴다. 그림 안에 들어갈 한국어 글자만 따옴표로 그대로 둔다.
4. 프롬프트 카드를 보여주고, 사용자가 [생성]을 누르면 만든다. [고쳐 쓰기]로 요청을 덧붙여 다시 쓸 수 있다.
5. 생성은 Gemini(`agy`의 `generate_image`)가 기본, agy가 연결되지 않았거나 실패하면 Codex(`image_generation`)로 한 번 대체한다.
6. 만든 이미지는 작업 폴더에 저장되고 채팅에 바로 보인다.

**비목표 (이번 범위 아님)**
- 참조 사진이 꼭 필요한 카테고리(부분 편집 C5, 의상 합성 C6, 보정 C10 등)의 실제 편집. 이번엔 카테고리를 판별해 "사진 편집은 다음 단계에서 지원해요"라고 안내만 한다. agy에 참조 이미지를 넘기는 방법이 아직 검증되지 않았다.
- 영상 카테고리(립싱크·사이드뷰 회전 등 8개 파일), 텍스트 분석용 3개 파일.
- 여러 장 일괄 생성, 이미지 갤러리, 이미지 편집기.

**반목표 (돌아가도 실패인 것)**
- 사용자 확인 없이 생성해서 무료 한도를 쓰는 것.
- 원문 프롬프트 파일을 저장소에 복사하는 것(일부에 외부 블로그 출처 표기).
- 템플릿에 실제 브랜드·IP 이름, 선정적 신체 수치, 인종 지정을 그대로 넣는 것 — 일반 표현으로 바꾼다.
- agy에 `generate_image` 외 도구 권한을 여는 것.

## 3. 제약 (확인된 사실)

- `agy -p`(headless)는 권한이 필요한 도구를 자동 거부한다. `--settings '{"permissions":{"allow":["generate_image"]}}'`를 주면 `generate_image`만 허용되어 생성된다(2026-11-06 실측: Flash Low, 약 43초, JPG 809KB).
- 생성 파일 위치: `~/.gemini/antigravity-cli/brain/<conversation_id>/<이름>.jpg`. 답변 본문에도 경로가 찍히지만, `--output-format json`의 `conversation_id`로 그 폴더의 새 이미지 파일을 찾는 쪽이 확실하다.
- 생성에 30~45초가 걸린다. 지금 agy 대화 시간 제한(35초)으로는 부족하다.
- Codex는 `image_generation` 기능이 켜져 있다(`codex features list`). 실제 생성·저장 위치는 아직 검증 안 했다 — 대체 경로를 구현하기 전에 한 번 확인한다.
- 사용자 Codex 계정은 무료(FREE) 플랜이라 한도가 작다.

## 4. 방식 (고려한 것과 고른 것)

| 방식 | 내용 | 득실 |
|---|---|---|
| **A. 규칙 판별 + 모델 작성 2단계 (선택)** | 규칙표로 카테고리를 고르고, 채팅 모델이 템플릿·규칙을 받아 영어 프롬프트 작성 → 확인 → 생성 | 자유 한국어 요청도 이해, 확인 단계로 한도 절약 / 호출 2번 |
| B. 규칙만으로 템플릿 채우기 | 키워드 사전으로 칸 채움 | 호출 1번 / 자유 표현·번역 불가로 품질 낮음 |
| C. 생성기에 한 번에 맡기기 | 규칙+요청을 생성기에 바로 | 단순 / 확인 단계 없음, 잘못 짚으면 한도 소모 |

사용자가 A를 골랐다(2026-11-06). 생성기는 처음엔 Codex 우선이었으나 사용자가 Gemini 기본 + Codex 대체로 바꿨다(2026-11-06). 확인은 "프롬프트 보여주고 한 번 눌러 승인"으로 정했다(2026-11-06).

## 5. 정해진 동작

1. **분류**: `TaskClassifier`에 `image` 모드를 추가한다. "이미지/그림/사진/일러스트/썸네일" + "만들어/그려/생성/뽑아" 조합이면 `image`. `ExecutionModeSchema`에 `image`를 더한다.
2. **카테고리 판별**: `config/image-prompt-catalog.json`의 카테고리별 트리거 단어로 고른다. 못 고르면 일반 사진(C1 계열 기본 템플릿)으로 간다. 참조 사진 필수 카테고리면 2단계로 가지 않고 안내 문구로 끝낸다.
3. **프롬프트 작성**: 선택된 연결의 `executeChat`에 "템플릿 + 해당 규칙 블록 + 사용자 요청 + 출력 형식(영어 프롬프트 한 덩어리, 설명 없이)"을 보낸다. 결과를 `image:prompt` 이벤트로 남기고 실행 상태를 `awaiting_approval`로 둔다.
4. **확인**: 채팅에 프롬프트 카드(카테고리 이름, 프롬프트 본문, [생성] [고쳐 쓰기])를 띄운다. [생성]은 기존 승인 경로처럼 API를 한 번 부른다.
5. **생성**: agy가 연결돼 있으면 `agy --model <이미지용 모델> --output-format json --settings <generate_image만 허용> -p "<프롬프트 + 이미지 1장 생성 지시>"`를 작업 폴더가 아닌 빈 임시 폴더에서 실행한다. 시간 제한은 180초. `conversation_id` 폴더에서 새 이미지 파일을 찾는다. 실패하거나 agy가 없으면 Codex로 한 번 시도한다.
6. **저장·표시**: 이미지를 `<작업 폴더>/.gon-images/<runId>-1.<확장자>`로 복사하고 `image:created` 이벤트에 상대 경로를 남긴다. API가 이 파일만 내려주는 경로를 하나 열고(작업 폴더 밖 경로 거부), 채팅이 그 주소로 이미지를 그린다.
7. **에러 문구**: 권한 거부·시간 초과·생성기 없음·사진 필요를 서로 다른 문장으로 보여준다.

## 6. 빌더에게 맡기는 것

- 카탈로그 JSON의 정확한 필드 이름과 13개 카테고리 템플릿 문장(분석 문서의 템플릿을 바탕으로, 원문을 옮기지 않고 다시 쓴다).
- 이미지용 agy 모델 이름 선택(현재 `agy models` 목록 기준), 프롬프트 카드의 시각 디자인.
- 이미지 제공 API 경로 이름과 이벤트 payload 모양.
- 테스트는 가짜 `CliRunner`로 agy/codex 호출 인자와 파일 찾기를 검증하고, 실제 생성은 수동 확인 1회로 남긴다.
