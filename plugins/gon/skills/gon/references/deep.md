# DEEP 모드 실행 지침

인증, 권한, 결제, 개인정보, 데이터베이스 마이그레이션, 대규모 아키텍처 리팩터링 등 고위험 작업에 적용한다.

## 실행 절차
1. **시작 기록**: `.gon/<run_id>/events.jsonl`에 `run.start`를 기록한다 (`mode: "deep"`).
2. **심층 구체화 (`refine`)**:
   - 모호한 설계 결정을 해결하기 위해 인터뷰 질문(최대 2라운드, 각 5개 이하)을 수행한다.
   - 보안/권한 제약 및 데이터 계약을 `.gon/<run_id>/brief.md`에 명시한다.
3. **상세 기획 (`plan`)**:
   - 상세 DAG, 인터페이스 계약 명세, 위험 대장(Risk Register), 롤백 절차를 수립하여 `.gon/<run_id>/plan.md`에 작성한다.
   - 복잡한 다중 모듈 구조 질의가 필요한 경우에 한해 `graphify`를 조건부 질의한다.
4. **전문 스킬 선별 (`route`)**:
   - 도메인별 ECC 전문 스킬(예: `ecc:security-review`, `ecc:api-design`)을 선별하여 작업에 배정한다.
5. **계획 승인 (`approve`)**:
   - 계획 전체 승인 외에도 파괴적 변경(삭제/스키마 변경)이 포함된 작업에 대해 사전 고지 및 승인을 확보한다.
6. **격리 실행 (`execute`)**:
   - 2~3개 워커 병렬 실행을 허용하되, 파일 충돌 위험이 있으면 순차 실행하거나 Git worktree 격리를 검토한다.
   - 각 전문가는 지정된 `[맡을 파일]` 외의 파일을 수정할 수 없으며, 벗어날 경우 작업을 즉시 멈춘다.
7. **강화된 검증 및 품질 리뷰 (`verify`)**:
   - 단위 테스트, 통합 테스트, 회귀 테스트뿐 아니라 전문 보안 점검 및 정적 분석을 수행한다.
   - 검증 실패 시 1회에 한해 수정 라운드를 진행하며, 동일 실패 지속 시 사용자에게 보고 후 대기한다.
8. **종료 및 보고**:
   - `run.end`를 기록하고 `node cli/dist/cli.js report <run_id>` 요약을 최종 보고에 포함한다.
