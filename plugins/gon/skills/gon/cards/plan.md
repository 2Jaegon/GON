# 작업 기획 대체 카드 (`cards/plan.md`)

외부 기획 스킬이 없을 때 이 카드의 절차를 따른다.

## 1. 목적
요구 명세(`brief.md`)를 바탕으로 작업 단계 분해, 의존성 관계, 파일 수정 권한 범위(`writeScope`)를 확정하여 `.gon/<run_id>/plan.md`를 작성한다.

## 2. 기획 원칙
- **작업 분해**: 각 작업은 단일 책임과 명확한 수용 기준을 가진다.
- **파일 소유권 분리 (`writeScope`)**:
  - 동시에 병렬 실행될 작업들은 수정 대상 파일 목록이 절대 겹치지 않아야 한다 (`writeScope(A) ∩ writeScope(B) == ∅`).
  - 겹치는 파일이 있다면 반드시 선후 의존 관계(`dependsOn`)를 설정하여 순차 실행한다.
- **기존 파일 덮어쓰기·삭제 목록**:
  - 기존 파일을 수정하거나 삭제할 경우 해당 목록을 명시적으로 작성하여 승인 대상에 포함한다.
- **검증 명령 명시**: 각 작업 및 전체 통합 후 실행할 구체적인 테스트/린트 명령을 포함한다.

## 3. `plan.md` 산출물 양식
```markdown
# 작업 실행 계획 (plan)

## 실행 모드: <FAST | STANDARD | DEEP>

## 작업 목록 (Tasks DAG)
- task_id: <작업1>
  title: <작업명>
  dependsOn: []
  writeScope: ["<수정 허용 상대 경로>"]
  skills: ["<선택된 스킬>"]
  acceptanceCriteria: ["<통과 기준>"]

## 기존 파일 변경/삭제 허용 목록
- <수정/삭제 예정 기존 파일 목록>

## 검증 계획 (Verification Commands)
- <실행할 테스트 또는 빌드 명령>
```
