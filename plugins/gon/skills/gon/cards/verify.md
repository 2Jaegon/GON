# 독립 검증 대체 카드 (`cards/verify.md`)

## 1. 목적
구현 작업이 완료된 후, 의도한 변경 범위만 수정되었는지 확인하고 수용 기준과 테스트를 철저히 검증하여 `.gon/<run_id>/verify.md`를 작성한다.

## 2. 검증 절차
1. **기준선 대조**:
   - 6단계 실행 직전에 `.gon/<run_id>/baseline.txt`에 기록해둔 `git status --porcelain` 결과와 현재 상태를 대조한다.
   - 워커에게 배정된 `writeScope` 밖의 기존 파일이 임의로 수정되지 않았는지 엄격히 확인한다.
2. **테스트 및 빌드 실행**:
   - 계획에 명시된 검증 명령(단위 테스트, 타입 검사, 린트 등)을 실제로 실행한다.
   - 실제로 실행되어 통과한 테스트만 `pass`로 기록한다. 미실행 테스트는 결코 `pass`로 보고하지 않으며 `unverified`로 표기한다.
   - 빌드 또는 필수 테스트 실패 시 작업을 완료로 보고하지 않는다.
3. **수용 기준 점검표 작성**:
   - `brief.md`에 정의된 각 수용 기준에 대해 증거(명령 결과, 파일 경로)와 함께 `pass / fail / blocked / unverified` 상태를 정리한다.
4. **산출물 기록**:
   - 검증 결과와 바뀐 파일 목록을 `.gon/<run_id>/verify.md`에 저장하고, node 이벤트(`stage: "verify"`)에 `files` 배열을 기록한다.
